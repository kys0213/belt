# plans/

의사결정·로드맵의 시점 기록을 남기는 디렉토리다. 현실과 어긋나도 고치지 않는다 — 현재 동작·규격 판단에는 쓰지 않는다 (그 역할은 `spec/`과 코드가 맡는다).

## 파일 규칙

- 파일명은 주제 중심으로 짓는다. 시점이 중요하면 날짜를 prefix로 붙인다 (예: `2026-04-v6-migration.md`).
- 각 파일 머리에 "작성 시점의 의사결정 기록이다. 현재 동작·규격의 신뢰 소스가 아니다" 류의 고지를 1줄 남긴다.

## 언제 쓰는가

- spec에서 걷어낸 버전 서사·마이그레이션 계획을 옮길 때
- 수용 기준 체크리스트 중 완료 후 갱신할 필요가 없는 것을 보관할 때
- 재논의의 배경(검토한 대안, 버린 이유)을 남길 때

## spec/draft/, spec/archive/ 와의 관계

- `spec/draft/`: 차기 규격 후보 — 승격 전까지는 신뢰 소스가 아니지만, 승격되면 spec이 된다.
- `spec/archive/`: 과거 규격의 동결 스냅샷 — 규격이었던 것의 기록.
- `plans/`: 규격이 아니라 규격에 이르기까지의 결정 기록 — 애초에 승격 대상이 아니다.

세 계층의 구분 기준은 CLAUDE.md의 "문서 계층 (Spec / Rules / Plan)" 절을 따른다.
